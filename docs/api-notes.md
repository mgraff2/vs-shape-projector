### f.1 Mod-supplied shaders: how they are found and compiled
- API: `IShaderProgram NewShaderProgram();` (`DECOMP/api/Vintagestory.API.Client/IShaderAPI.cs:12`), `IShader NewShader(EnumShaderType shaderType);` (18), `int RegisterFileShaderProgram(string name, IShaderProgram program);` (27), `int RegisterMemoryShaderProgram(string name, IShaderProgram program);` (36), `IShaderProgram GetProgram(int renderPass);` (43), `IShaderProgram GetProgramByName(string name);` (50), `bool ReloadShaders();` (56). `IShaderProgram.AssetDomain { get; set; }` — `IShaderProgram.cs:14`.
- `RegisterFileShaderProgram` sets `LoadFromFile = true` and calls `ShaderRegistry.RegisterShaderProgram(name, program)` — `DECOMP/lib/Vintagestory.Client.NoObf/ShaderAPI.cs:42-46`. That assigns a pass id, `PassName = name`, and immediately runs `LoadShaderProgram` (reads the files) — `ShaderRegistry.cs:100-107`. **It does not compile**; the caller must call `program.Compile()` (vanilla: `RiftRenderer.cs:50-57`).
- File lookup: `new AssetLocation(program.AssetDomain, "shaders/" + passName + ".vsh"/".fsh"/".gsh")` resolved with `AssetManager.TryGet_BaseAssets` — `ShaderRegistry.LoadShader`, `ShaderRegistry.cs:234-263`. `AssetLocation.Domain` returns `"game"` when the domain is null (`DECOMP/api/Vintagestory.API.Common/AssetLocation.cs:28-33`) and equality compares `Domain` (470-481), so **a program with `AssetDomain` unset looks in `game:shaders/`**. `TryGet_BaseAssets` is a plain lookup in `AssetManager.Assets`, the dictionary holding every loaded asset from every origin including mods (`DECOMP/lib/Vintagestory.Common/AssetManager.cs:19,217-228`). ⇒ **Recipe: set `prog.AssetDomain = "shapeprojector"` and ship `assets/shapeprojector/shaders/<name>.vsh` + `<name>.fsh`.** Missing file → error "Shader file {0} not found" and `LoadError = true` (250-257). Precedent that a mod folder's `shaders/` is loaded this way: vanilla's rift shader lives in `ASSETS/survival/shaders/rift.{vsh,fsh}` (a mod folder, domain `game`) and is loaded through exactly this path.
- `#include`: `HandleIncludes` replaces `^#include <file>` lines from a static `includes` dictionary keyed by **bare file name**, filled from `AssetManager.GetMany(AssetCategory.shaderincludes)` plus all `AssetCategory.shaders` assets, across all domains — `ShaderRegistry.cs:190-199, 340-367`. ⇒ engine includes (`fogandlight.fsh`, `vertexflagbits.ash`, `oit.fsh`, …) work in a mod shader; a mod file with the same name as an engine include **overwrites** it (same dictionary key) — never name our files like engine ones.
- Reload: `ShaderRegistry.ReloadShaders` disposes and nulls **every** program slot, re-registers only engine programs, then reloads (`ShaderRegistry.cs:148-175`). Mod programs are gone after that; the engine then fires `IClientEventAPI.ReloadShader` (`IClientEventAPI.cs:126`; triggered from `ClientMain.cs:774,779` on `ssaoQuality`/`minbrightness` setting changes, the debug reload command `ClientSystemDebugCommands.cs:656`, and the escape menu `GuiDialogEscapeMenu.cs:419`). **Subscribe `capi.Event.ReloadShader += LoadShader` and re-create/register/compile the program there, returning `Compile()`'s result** — exactly `RiftRenderer.cs:45-57`.
- Default uniforms: `ShaderProgramBase.Use()` fills `zNear`, `zFar`, `lightPosition`, `shadowIntensity`, shadow maps, `viewDistance`… when the program's includes contain `fogandlight.fsh`; fog spheres / point lights / `flatFog*` / `nightVisionStrength` for `fogandlight.vsh`; shadow matrices for `shadowcoords.vsh` — `ShaderProgramBase.cs:276-318`. Everything else in your shader (matrices, `rgbaFogIn`, `fogMinIn`, `fogDensityIn`, `rgbaAmbientIn`, `rgbaLightIn`, samplers) you set yourself; vanilla does so at `RiftRenderer.cs:97-111`.

### f.2 Scene depth texture: what exists and when it is safe to read
- `EnumFrameBuffer.Primary = 0`, `Transparent = 1` — `DECOMP/api/Vintagestory.API.Client/EnumFrameBuffer.cs`. `capi.Render.FrameBuffers[0].DepthTextureId` is the primary depth texture, format `DepthComponent32f` (`PixelInternalFormat 33191`, `PixelType 5126` = float) — `ClientPlatformWindows.cs:1201-1213`; rift.fsh's comment agrees ("depth from gbuffer depth, a float32 texture", `ASSETS/survival/shaders/rift.fsh:29`).
- **The Transparent (OIT) framebuffer attaches that same primary depth texture as its depth attachment** — `GL.FramebufferTexture2D(..., DepthAttachment(36096), ..., list[0].DepthTextureId, 0)` at `ClientPlatformWindows.cs:1288`, with depth writes off and depth test on during the OIT stage (1686-1687). Sampling a texture attached to the currently bound framebuffer is a GL feedback-loop condition; whether it is defined with the depth mask off is a GL-spec question **I cannot verify from game source, and no engine shader does it during OIT** — Not found. Do not build on it.
- **Where vanilla reads it:** `RiftRenderer` registers at `EnumRenderStage.AfterBlit` (stage 9, `RiftRenderer.cs:41`) and binds `primaryFb` + `depthTex` from `FrameBuffers[0]` (103-104). By then the primary buffer has been blitted to the default framebuffer, so the primary depth texture is **not** attached to the bound framebuffer. GL state at `AfterBlit` is set by `ScreenManager.Render`: ortho `pMatrix`, `GlDepthFunc(Lequal)`, default depth buffer cleared to 20000, `GlEnableDepthTest()`, `GlDisableCullFace()`, `GlToggleBlend(on: true)` — `DECOMP/lib/Vintagestory.Client/ScreenManager.cs:735-742`. Because the **default framebuffer's depth buffer is cleared** before AfterBlit (739-740), the hardware depth test there says nothing about world geometry; occlusion must come from the shader's own compare (which is what rift.fsh does). `RiftRenderer` also sets `GLDepthMask(false)` (96, restored at 147). The perspective matrices are still available via `capi.Render.CurrentProjectionMatrix` / `CameraMatrixOriginf` (RiftRenderer uses them at 105, 126).

### f.3 Linear depth in the engine's includes
- `float linearDepth(float depthSample)` — `depthSample = 2.0*depthSample - 1.0; return 2.0*zNear / (zFar + zNear - depthSample*(zFar - zNear));` — `ASSETS/game/shaderincludes/fogandlight.fsh:214-219`; inverse `float depthSample(float linearDepth)` (222-227). `zNear`/`zFar` are uniforms declared in that include (5-6, defaults 0.3 / 1500) and set by `Use()` (f.1). The value returned is normalized (zNear/zFar ≤ z ≤ 1); **inference, not in source: multiply by `zFar` to get view-space distance in blocks.**
- Vanilla's depth-tolerance compare, verbatim (`rift.fsh:26-33, 59`): `x = gl_FragCoord.x * invFrameSize.x; y = …; z1 = linearDepth(texture(depthTex, vec2(x,y)).r); z2 = linearDepth(gl_FragCoord.z); aDiff = max(0, z2 - z1) * 1000; if (aDiff > 2) discard; … col.a = clamp(col.a - aDiff, 0, 1);` — fragments behind the scene by more than a small normalized amount are discarded, nearer ones fade. `invFrameSize` = `1/FrameWidth, 1/FrameHeight` (`RiftRenderer.cs:106-111`).

### f.4 Concrete cited recipe for a bounded see-through (Renderer, steps 5/6)
1. **Stage:** `EnumRenderStage.AfterBlit` (as `RiftRenderer.cs:41`). Keep the step-1 OIT draw for the normal depth-tested look and add a second pass at AfterBlit for the "behind terrain within tolerance" look — or move everything to AfterBlit and do all visibility in the shader.
2. **Program:** `prog = capi.Shader.NewShaderProgram(); prog.VertexShader = capi.Shader.NewShader(EnumShaderType.VertexShader); prog.FragmentShader = capi.Shader.NewShader(EnumShaderType.FragmentShader); prog.AssetDomain = "shapeprojector"; capi.Shader.RegisterFileShaderProgram("projectorghost", prog); prog.Compile();` inside a `LoadShader()` that is also subscribed to `capi.Event.ReloadShader` (`RiftRenderer.cs:45-57`; `IShaderProgram.AssetDomain`, `IShaderProgram.cs:14`). Files: `assets/shapeprojector/shaders/projectorghost.vsh` / `.fsh`. Vertex layout for our RGBA-only mesh: `layout(location=0) in vec3 vertexPositionIn; layout(location=1) in vec4 vertexColor;` (as `blockhighlights.vsh:4-5`, §d.2).
3. **Per frame:** stop `CurrentActiveShader`; `prog.Use()`; `prog.UniformMatrix("projectionMatrix", capi.Render.CurrentProjectionMatrix)`; `prog.UniformMatrix("modelViewMatrix", Matrixf.Identity().Translate(pos - CameraPos).ReverseMul(capi.Render.CameraMatrixOriginf).Values)`; `prog.BindTexture2D("depthTex", capi.Render.FrameBuffers[0].DepthTextureId, 0)`; `prog.Uniform("invFrameSize", 1f/capi.Render.FrameWidth, 1f/capi.Render.FrameHeight)`; `prog.Uniform("seeThroughDepth", cfg.seeThroughDepth)`; `capi.Render.GLDepthMask(false)`; `RenderMesh`; `prog.Stop()`; `GLDepthMask(true)` (`RiftRenderer.cs:96-147`; `GLDepthMask` `IRenderAPI.cs:278`). Blending is already on at AfterBlit (`ScreenManager.cs:741`).
4. **Fragment:** `#include fogandlight.fsh` (for `linearDepth`); `float zScene = linearDepth(texture(depthTex, gl_FragCoord.xy * invFrameSize).r); float zFrag = linearDepth(gl_FragCoord.z); float behind = (zFrag - zScene) * zFar;` (the `* zFar` conversion is my inference, f.3) `if (behind > seeThroughDepth) discard; outColor = vec4(color.rgb, color.a * (behind <= 0.0 ? 1.0 : 1.0 - behind / seeThroughDepth));`. This is `rift.fsh:29-33,59` with the constant replaced by a uniform.
5. **Cost:** one extra draw of the same VBO per projector per frame plus one depth-texture fetch per fragment; no engine changes.
6. **Fallback needing no custom shader (verifiable today):** inside the OIT stage draw the mesh twice with the engine `Blockhighlights` program: once normally (depth-tested, full alpha), then `capi.Render.GLDisableDepthTest()`, draw a very-low-alpha copy, `GLEnableDepthTest()` (`IRenderAPI.cs:265,270`; the engine re-enables depth test after OIT regardless, `ClientMain.cs:1176-1177`). This shows the outline through *everything* at low alpha — no distance bound; it is the spec §9 "wallhack" case and acceptable only as a stopgap.

**Consequence for the spec:** a bounded `seeThroughDepth` is implementable with a mod shader at `AfterBlit` following the rift precedent; it is not available inside the OIT stage, so ghost cubes render either OIT-composited (current step-1 path) or in an AfterBlit pass with plain alpha blending — a design choice for the Renderer. `GLDepthFunc` on `IRenderAPI` remains **Not found** (the engine has `Platform.GlDepthFunc`, `ScreenManager.cs:737`, but it is not exposed to mods).

### g.3 Column height semantics (client side)
- `int GetRainMapHeightAt(BlockPos pos)` / `(int posX, int posZ)` return `mapChunk.RainHeightMap[z%32*32 + x%32]`, or **0 when the map chunk is not loaded** — `DECOMP/lib/Vintagestory.Common/BlockAccessorBase.cs:725-745`. Treat 0 as "unloaded" (spec §5a fixed-Y fallback). `GetTerrainMapheightAt` is the worldgen-time map, never updated (`IBlockAccessor.cs:475-480`) — not usable for drape.
- What the rain map holds: `UpdateRainHeightMap(oldBlock, newBlock, pos, mapchunk)` — `BlockAccessorBase.cs:791-830`: if the new block is **not** `RainPermeable`, height = max(old, pos.Y); if a non-permeable block at the recorded height became permeable, it walks downward while `worldmap.Blocks[GetBlockId(x, y, z, 3)].RainPermeable` (layer 3 = `BlockLayersAccess.FluidOrSolid`: "Returns the contents of the fluid layer, unless it is empty in which case returns the solid blocks layer - useful for generating the RainHeightMap", `BlockLayersAccess.cs:34-37`). It is called from `SetSolidBlockInternal` (143) and from the fluid-layer setter (198), i.e. **on the client too**, for every `SetBlock` through the block accessor (which the packet handlers above use).
- `Block.RainPermeable` defaults to `false` (`Block.cs:323`, doc 320-322); only air is forced `true` (`DECOMP/lib/Vintagestory.Common/BlockList.cs:229`) plus blocks whose JSON sets `rainPermeable` (tallgrass via `rainPermeableByType`, `ASSETS/survival/blocktypes/plant/tallgrass.json:141`; aquatic plants, oil lamp, tapestry, ropebeam, mechanics axles/gears per directory grep). **Water (`liquid/water.json`) and leaves (`plant/leaves/normal.json`) do not set it → both count as surface.** So `GetRainMapHeightAt` = Y of the topmost non-air, non-`rainPermeable` block in fluid-or-solid: water top, leaf canopy and snow layers all stop it.
- **Drape implementation (cited calls):**
  - `treatFluidAsSurface = true`: `y = capi.World.BlockAccessor.GetRainMapHeightAt(x, z)`; outline at `y + 1` (+ layer offset).
  - `treatFluidAsSurface = false`: start at that `y`; while `GetBlock(x, y, z, BlockLayersAccess.Fluid)` (`IBlockAccessor.cs:168`; `Fluid = 2`, `BlockLayersAccess.cs:29-32`) `.IsLiquid()` (`CollectibleObject.cs:3291`; its doc says to use the Fluid layer) decrement `y`; the bed is the first non-liquid. Ice sits in the fluid layer but `IsLiquid()` is false for it, so ice is "surface" in both modes.
  - Leaves: ignoring canopy would need a manual descent through `BlockMaterial == EnumBlockMaterial.Leaves` (`Block.cs:131`); the height map cannot do it. The spec does not ask for it.

**Consequence for the spec:** §5a's "recompute on block-change events" is sound for solid-block edits (local and remote); fluid-only changes need a periodic re-sample. `GetRainMapHeightAt` returning 0 for unloaded columns matches the spec's "unloaded columns fall back to fixed Y".

- **Face `glow` is baked at tesselation time.** `ShapeElementFace.Glow` (`ShapeElementFace.cs:29`) is combined with the tesselation call's `generalGlowLevel`: `flags = ((element.ZOffset & 7) << 8) | (meta.GeneralGlowLevel + shapeElementFace.Glow)` — `DECOMP/lib/Vintagestory.Client.NoObf/ShapeTesselator.cs:469`; glow occupies bits 0..7 (`VertexFlags.GlowLevelBitMask = 255`, `VertexFlags.cs:37`). A "glow face property toggled via BE state" is therefore not a live switch on the static chunk mesh; it becomes one of the following.
- **Option A — two block variants + `ExchangeBlock` (cheapest, vanilla-standard).** `void ExchangeBlock(int blockId, BlockPos pos);` — "without calling OnBlockRemoved or OnBlockPlaced, which prevents any block entity from being removed or placed" (`IBlockAccessor.cs:262-266`); the BE gets `OnExchanged(Block block)`, which calls `MarkDirty(redrawOnClient: true)` when the block changed and updates `Block` (`BlockEntity.cs:314-321`). Vanilla: `world.BlockAccessor.ExchangeBlock(world.GetBlock(CodeWithVariant("state", "opened")).Id, position)` — `BlockCokeOvenDoor.cs:21`; `RegistryObject.CodeWithVariant(string type, string value)` (`RegistryObject.cs:121`). The client receives packet 58 and fires `BlockChanged` (`GeneralPacketHandler.cs:106-113`). Per-variant light via `lightHsvByType` (`ASSETS/survival/itemtypes/resource/gear.json`: `lightHsvByType: { "gear-temporal": [32, 5, 2] }`) or per-type `lightHsv` (`blocktypes/machine/jonas/jonaslamp.json`). The `-off`/`-on` shapes differ only in the ring faces' `"glow"` values.
- **Option B — BE-tesselated mesh with runtime glow.** Override `BlockEntity.OnTesselation(ITerrainMeshPool mesher, ITesselatorAPI tessThreadTesselator)` (`BlockEntity.cs:543`; doc 535-542: runs on the tesselator thread, return true to replace the default mesh), build the mesh with `tessThreadTesselator.TesselateShape(typeForLogging, shape, out mesh, texSource, meshRotationDeg, generalGlowLevel, …)` (`ITesselatorAPI.cs:99`) or apply `mesh.SetVertexFlags(glow & 255)` to a cached mesh (`MeshData.cs:1309-1319`, binary OR), then `mesher.AddMeshData(mesh)` (`ITerrainMeshPool.cs:10`). To retesselate after a state change call `MarkDirty(true)` (`BlockEntity.cs:463-471` → `MarkBlockDirty`: "Client side: Triggers a block changed event and redraws the chunk", `IBlockAccessor.cs:407-412`). Vanilla: `BEBehaviorShapeFromAttributes.OnTesselation` adds its own mesh (`:224-230`); the **Jonas lamp** toggles by rewriting its `Type` between `lightsource/off/…` and `lightsource/on/…`, calling `Blockentity.MarkDirty(true)`, reloading its mesh and relighting — `BEBehaviorControlPointLampNode.cs:56-70` (light comes from that type's `lightHsv`, 106-107).
- **Cost (from the cited paths):** A = one packet + one chunk retesselation, no per-frame cost, two blocktype variants to maintain, block light can differ per variant. B = one chunk retesselation, one blocktype, glow only (block light level is a block property, so it cannot change without a variant). Neither is per-frame.

**Consequence for the spec:** §7's "two block variants `-off`/`-on`, or a `glow` face property toggled via BE state" — the first is Option A; the second exists only as Option B (retesselation with `generalGlowLevel`/`SetVertexFlags`), not as a live toggle of a static face flag. Either satisfies the spec; A is recommended if the ring should also emit light.

### l.1 The render context a GUI element draws in

- Dialogs render during **`EnumRenderStage.Ortho`**, on the **default framebuffer**, with the **gui shader bound for the whole stage**: `ClientMain.RenderToDefaultFramebuffer` does `guiShaderProg = ShaderPrograms.Gui; guiShaderProg.Use(); OrthoMode(window); TriggerRenderStage(EnumRenderStage.Ortho, dt); guiShaderProg.Stop();` — source: `DECOMP/lib/Vintagestory.Client.NoObf/ClientMain.cs:1212-1225`.

### m.1 Key-event override surface on GuiDialog, and the full dispatch order

- Overrides: `public virtual void OnKeyDown(KeyEvent args)` — `DECOMP/api/Vintagestory.API.Client/GuiDialog.cs:472`; `public virtual void OnKeyPress(KeyEvent args)` — `:494`; `public virtual void OnKeyUp(KeyEvent args)` — `:523`. - Dialog gets keys only while focused: `GuiManager.OnKeyDown` loops opened dialogs calling `item.OnKeyDown(args)` gated by `ShouldReceiveKeyboardEvents()` (`GuiManager.cs:236-266`; ESC intercept for keyCode 50 at :251-255 runs before that loop), and `ShouldReceiveKeyboardEvents() => focused` — `GuiDialog.cs:735-738`.
- **Elements consume BEFORE dialog-level logic — if the override calls base first.** `GuiDialog.OnKeyDown` body dispatches to every composer (`Composers[i].OnKeyDown(args, focused)`) and returns if `args.Handled` (`GuiDialog.cs:474-482`), then checks its own toggle-key close (:483-487). `GuiComposer.OnKeyDown(KeyEvent, bool haveFocus)` walks interactive elements until handled, then does Tab-cycling (keyCode 52) — `DECOMP/api/Vintagestory.API.Client/GuiComposer.cs:576-611`. So the correct shape is: `override OnKeyDown` → `base.OnKeyDown(args); if (args.Handled) return;` → own hotkey logic → `args.Handled = true` on match. Logic placed before the base call would fire while the player types.
- A **focused** editable text element swallows nearly everything: `GuiElementEditableTextBase.OnKeyDown` acts only `if (base.HasFocus)` (`DECOMP/api/Vintagestory.API.Client/GuiElementEditableTextBase.cs:613-619`) and its `OnKeyDownInternal` ends with `args.Handled = handled` where `handled = multilineMode || args.KeyCode != 52` (:636, :784) — i.e. **every key except Tab (GlKeys.Tab = 52, `GlKeys.cs:71`) is consumed while a single-line input has focus**. ### m.2 Typing guard (the Tallybook bug)

### m.4 Do CharacterControls hotkeys (the "O" hide key) still fire while the dialog is open?

- Gating flag: `HotKey.DidPress(...)` rejects only when `(KeyCombinationType == CharacterControls || MovementControls) && !allowCharacterControls` — `DECOMP/api/Vintagestory.API.Client/HotKey.cs:60-62` (same in `FallbackDidPress`, :94-98). The flag passed in is `ClientMain.AllowCharacterControl`, declared `= true` at `ClientMain.cs:101` — and **no assignment to it exists anywhere else in the decompiled lib** (searched `DECOMP/lib`; only readers at `ClientMain.cs:1885, 1922` and `HotkeyManager.cs:287` in `DECOMP/lib/Vintagestory.Client/HotkeyManager.cs`). So opening a dialog does NOT flip any character-controls gate.
- Therefore the only thing standing between a pressed letter key and a CharacterControls hotkey while our dialog is open is **whether the dialog chain marked the event Handled** (dispatch order, m.1). Concretely: focused text input → everything but Tab is consumed, "O" never reaches the hotkey (that is also why vanilla typing doesn't trigger hotkeys); no text focus and the dialog doesn't handle "O" → it falls through to `TriggerHotKey` at `ClientMain.cs:1885` and **the world hotkey fires with the dialog open**. `HotkeyManager.TriggerHotKey` has no dialog awareness (`DECOMP/lib/Vintagestory.Client/HotkeyManager.cs:121-150`; only `ShouldTriggerHotkeys` :123 and gamemode checks :138).
- **Decision input:** reusing plain letter keys as dialog-local hotkeys is safe only if the dialog's `OnKeyDown` consumes them (sets Handled) — then the world hotkey is shadowed while the dialog is focused, which may itself surprise the player. Non-letter keys (PageUp/PageDown/+/-) collide with no default CharacterControls binding and are the safer choice; the existing "O" hide hotkey keeps working with the dialog open as long as no text input is focused and the dialog leaves "O" unhandled.

### m.5 Recommended shape (assembled from the citations above)

```csharp
public override void OnKeyDown(KeyEvent args)
{
    base.OnKeyDown(args);                    // composers first: focused inputs + Tab cycling (GuiDialog.cs:472-488)
    if (args.Handled) return;                // a focused text/number input consumed it (m.1)
    if (SingleComposer?.CurrentTabIndexElement is GuiElementEditableTextBase) return;  // typing guard (m.2)
    switch (args.KeyCode)
    {
        case (int)GlKeys.PageUp:      /* layer up */         args.Handled = true; break;
        case (int)GlKeys.PageDown:    /* layer down */       args.Handled = true; break;
        case (int)GlKeys.Plus:
        case (int)GlKeys.KeypadAdd:   /* radius +1 */        args.Handled = true; break;
        case (int)GlKeys.Minus:
        case (int)GlKeys.KeypadSubtract: /* radius -1 */     args.Handled = true; break;
    }
}
```
Fires only while the dialog is open and focused (`ShouldReceiveKeyboardEvents => focused`, GuiDialog.cs:735-738); never while typing; keys marked Handled never fall through to world hotkeys (ClientMain.cs:1848-1887).

### o.2 gui shader attribute layout vs. MeshData upload — the one trap

`ASSETS/game/shaders/gui.vsh` declares explicit locations: `layout(location = 0) in vec3 vertexPositionIn;` (:4), `layout(location = 1) in vec2 uvIn;` (:5), `layout(location = 2) in vec4 colorIn;` (:6), `layout(location = 3) in int renderFlagsIn;` (:13), `layout(location = 4) in float damageEffectIn;` (:14), `layout(location = 5) in int jointId;` (:15).

But `UploadMesh(MeshData)` assigns VBO attribute slots **sequentially over whichever arrays are non-null**, in fixed order xyz → Normals → Uv → Rgba → Flags → customs: a slot counter starts at 0 and increments once per present array — `ClientPlatformWindows.cs:3041-3117` (xyz at :3053-3064, Normals :3066-3078, Uv :3079-3091, Rgba :3092-3104 as 4x UNSIGNED_BYTE normalized, Flags :3105-3117 as integer attrib).

- **Consequence (read from the two files above): a MeshData with xyz + Rgba but `Uv == null` puts Rgba at location 1 = `uvIn`, not location 2 = `colorIn`. Per-vertex color would be misread as texture coordinates.** Do not build the mesh that way.
- **(a) Per-vertex rgba IS honored through the gui shader** when the array order matches the shader locations: keep `Uv` and `Flags` allocated (default ctor flags; fill uv with `AddVertex(x,y,z,0,0,color)` or leave zeros) and no Normals/customs → xyz=0, Uv=1, Rgba=2, Flags=3, exactly matching gui.vsh. Uniforms: `applyColor = 1` and `rgbaIn = (1,1,1,1)` — the vertex shader does `color = rgbaIn;` then `if (applyColor == 1) color *= colorIn;` (`gui.vsh:59-61`); `noTexture = 1` makes the fragment shader output that interpolated color directly: `if (noTexture > 0) { outColor = color; }` (`gui.fsh:60-61`). Also set `extraGlow = 0` (glow adds via `renderFlagsIn`+`extraGlow`, `gui.vsh:54-56`, applied `gui.fsh:89`) and `normalShaded = 0` (else brightness is modulated by the flags-packed normal, `gui.fsh:98-101`); with Flags filled as 0 the normal is `unpackNormal(0)`. `alphaTest` must stay below the line alpha (`gui.fsh:96` discards when `outColor.a <= alphaTest`).
- **(b) Uniform-color alternative** (no per-vertex color needed): `applyColor = 0` → `color = rgbaIn` unconditionally (`gui.vsh:59-61`), `noTexture = 1` → `outColor = color` (`gui.fsh:60-61`); `colorIn` and `uvIn` are then never consumed on the output path (uv only feeds the `darkEdges`/`damageEffect`/texture branches, `gui.fsh:46,52-53,64-81`, all off when those uniforms are 0). Attribute locations left unbound by the VAO read the GL current generic attribute constant, not garbage memory (*inference from GL semantics, labeled — same caveat class as §l.2's scissor note*); but since o.2(a) costs nothing (the ctor allocates Uv/Flags by default), prefer the matched-layout mesh and never rely on unbound attribs.

### o.4 GuiElementCustomRender subclassing

### p.6 Retrieving an icon button by key, and the disabled-state truth

- **Getter:** `public static GuiElementToggleButton GetToggleButton(this GuiComposer composer, string key)` — "Gets the toggle button by name in the GUIComposer" — source: `DECOMP/api/Vintagestory.API.Client/GuiComposerHelpers.cs:455-461`. There is no `GetIconButton`; `AddIconButton` creates a `GuiElementToggleButton` (p.1), so `SingleComposer.GetToggleButton("addlayerout")` is the retrieval call for the key passed to `AddIconButton`.
- **`Enabled` exists but the toggle button ignores it.** Declaration: `protected bool enabled = true;` + `public virtual bool Enabled { get; set; }` on `GuiElementControl` ("An element that allows input and can be disabled") — source: `DECOMP/api/Vintagestory.API.Client/GuiElementControl.cs:8-22`; inherited by the icon button via `GuiElementToggleButton : GuiElementTextBase` (`GuiElementToggleButton.cs:9`) `: GuiElementControl` (`GuiElementTextBase.cs:5`). But inside `GuiElementToggleButton` the **only** consumer of `enabled` is `public override bool Focusable => enabled;` (`GuiElementToggleButton.cs:40`):
  - (a) input is **NOT blocked** — `OnMouseDownOnElement` flips `On` and invokes the handler with no enabled check (`GuiElementToggleButton.cs:175-181`);
  - (b) the draw path renders **no disabled visual** — `RenderInteractiveElements` only picks pressed/released/hover textures (`GuiElementToggleButton.cs:161-168`), and neither compose path branches on `enabled` (searched the file: one hit, line 40).
- **What vanilla does for a visibly disabled button** exists only on `GuiElementTextButton` (the AddButton/AddSmallButton element): it composes a `disabledTexture` that is a black 40 %-alpha overlay (`SetSourceRGBA(0.0, 0.0, 0.0, 0.4)` on a 2x2 surface, `GuiElementTextButton.cs:129-137`) rendered over the button when `!enabled` (`:205-208`), and its click handler is guarded `if (enabled && currentlyMouseDownOnElement && ...)` (`:281`). **Nothing in vanilla dims or gates a disabled icon button** — no `GuiElementToggleButton` subclass or call site does (searched `DECOMP/api`, `DECOMP/lib`, `DECOMP/survival`, `DECOMP/essentials`).
- **Consequence for the spiral-disabled "Add layer out" button:** set `GetToggleButton(key).Enabled = false` for semantics/focus, but ALSO (1) guard the `Action<bool>` callback itself (the click will still arrive), and (2) convey the disabled look yourself — the icon tint is `Font.Color` in the normal draw (`api.Gui.Icons.DrawIcon(..., Font.Color)`, `GuiElementToggleButton.cs:100`; the ON state uses `GuiStyle.DialogDefaultTextColor`, `:134`), so compose the button with a grayed `CairoFont` via the `AddIconButton(icon, font, ...)` overload (`GuiComposerHelpers.cs:501-508`) when the spiral shape is selected. The font is baked at compose time, so switching between enabled/disabled look means re-composing the dialog (the projector dialog already re-composes on shape change) — there is no runtime dim toggle to cite.
